The [command contract](../../../reference/command-execution.md) defines scope, normalized input, current `authorize`/`replay`, explicit `persistResult`, audit/outbox and stable failures. Same logical request with changed accepted input conflicts. No generic wrapper may blindly persist a response or rerun a workflow on replay. Financial and single-use business constraints remain mandatory even when the caller changes the request ID. Existing mutations without an adopted contract are not automatically retryable.

The [private-file contract](../../../reference/private-file-foundations.md) defines owner/purpose, input/result types, size/type bounds, transaction phases, result unavailability and retention. Upload signing, byte reads/copies, rendering and provider calls occur outside business SQL; every publication phase reauthorizes in its own transaction. External-only historical attachments never become private grants. Their metadata stays available for the owning migration, which must resolve required historical downloads before release.

The [durable cron contract](../../../reference/cron-runtimes.md) defines occurrence identity, authoritative job references, dispatch and retry. Feature handlers load current school/resource facts; queue payloads and receipt metadata confer no authority. Provider delivery is at least once with per-channel completion and residual uncertain-result duplicate risk, not exactly once.

## Verification procedure

Run commands from their owning repository, preserving the exact command and output. Check the current scripts before executing them, and classify a failed setup separately from a failed assertion. After a source correction, verify the corrected state rather than reusing an earlier green log.

- Backend: `bun run verify` (hygiene/generated drift, quality, build, unit/service/persistence/API tests); `bun run test:integration` (service/adaptor and HTTP contracts); `bun run test:integration:native` (fresh loopback PostgreSQL cluster, independent pools and guaranteed cleanup). The native runner never uses a project `DATABASE_URL` as a reset target.
- Seed changes: `bun run test:integration:seed`. Live-auth cases need an explicitly disposable local identity runtime matching the harness; keep delivery synthetic/log-only and stop the fixture after tests. Do not infer a production target from environment defaults. CLI mutation seeds use admitted HTTP/in-process workflows; declarative fixtures contain no provisioning side effects.
- Identity changes: sibling `edaya_identity` → `bun run verify`, plus the changed auth/directory/public-admission cases. School authority remains in the backend.
- Public contract changes: follow the [cross-repository generation procedure](../../../reference/cross-repo-workflow.md). Regenerate TypeScript and Dart; do not hand-edit generated files. Refresh materialized web file dependencies with `bun install --frozen-lockfile --force`, compare installed bindings, then run web repository hygiene and uncached `quality`, `build` and `test` through Turbo. Mobile runs its generated/brand checks, analysis and tests via `melos run verify`.
- UI changes: follow each repository's current specifications and test selected-profile behavior, loading/empty/error/conflict states, explicit retry, localization and context invalidation. Read renewal does not authorize mutation replay. Shared backend mechanisms do not satisfy a feature's missing web/mobile screen.

For each checkpoint record starting revisions and dirty-tree provenance; final source digest; exact commands, counts, exit codes and log locations; applied-to-test migrations; fixture/environment identity and cleanup; generated/installed client alignment; deviations and remaining limitations. Distinguish local test evidence from actual browser/device/provider/deployment evidence. A checked requirement needs scope-matched proof, and the Plan 06 candidate must match the code and contracts actually tested.

The shared web mutation runners and mobile mutation feedback contract are qualified in [client acceptance](00-client-acceptance.md). Seed owner initialization is an internal fixture-only capability, never a feature authorization shortcut. See the [completed exit matrix](00-exit.md) for final source and test provenance.
