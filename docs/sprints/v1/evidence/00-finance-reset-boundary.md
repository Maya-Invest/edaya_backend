# Disposable finance target and preservation boundary

Owner: Codex. Recorded 2026-09-14 for Plan 00. This is the baseline inventory handed to Plan 03; it does not start the account-model implementation or perform a reset.

The selected implementation/cutover test target is a fresh loopback PostgreSQL cluster created by [the native test runner](../../../../tooling/integration-tests/src/native/run.ts). Each invocation creates its own temporary directory and database, binds `127.0.0.1` on an allocated port, passes its own `EDAYA_NATIVE_TEST_URL` to the child and destroys only that cluster afterward. It never selects a project `DATABASE_URL`. The current native run passed 31 tests and stopped its cluster (`/private/tmp/edaya-v1-baseline/upload-formats-native.log`). All records in this target are synthetic and disposable. The current target lifetime ends with each run; Plan 03 must create a fresh target for its cutover scenario.

No existing local `.data`, staging, production or identity database has been selected for finance reset. The user's approved finance disposability does not make non-finance records disposable. The existing whole-schema [remote reset command](../../../../tooling/db-migrate/scripts/reset-target.ts) and [clearAllTables](../../../../package/adaptor-postgres/src/lib/schema-init.ts) exceed this finance scope and cannot implement its cutover. Plan 03 supplies a separate target-validated finance operation through the existing tooling, with no remote default. Any later selected environment needs its exact identity and preservation evidence recorded again.

## Current finance records and derived dependencies

School membership for `student_fees` and `payments` must be resolved through current parents; neither table contains a `school_id`. The [schema](../../../../package/adaptor-postgres/src/schema/finances.ts) currently stores these relationships as text columns, so an inventory must detect missing or disagreeing parents explicitly rather than treating absent foreign keys as proof of independence.

## Records that must survive

Preserve Central Identity users, sessions, authentication and directory data; consortiums/schools, school owners, staff, service identities, permission assignments and invitations; teachers/assignments; students, guardians and guardian–student links; academic years/periods, grades, classes and enrollments; subjects, curriculum, schedules, sessions, attendance, assessments/results and report-card records; health, incidents, discipline and notes; non-finance attachments and references; resources, messaging, notification registration, cron schedules and unrelated durable history. Applied migration history is preserved.

The cutover acceptance fixture must contain two schools, related/unrelated guardians and children, staff authority, academic records and both finance and non-finance attachments. Before deletion, capture row identities and canonical content digests of the preservation set; compare them after cutover and finance reseeding. Counts alone cannot detect changed records. The finance operation must reject a foreign/missing parent, preserve cross-school rows, roll back partial failure, reconcile new accounts and leave old immutable references unable to trigger stale effects. These are Plan 03 implementation/acceptance requirements; they have not yet been executed.
