Measured on 5 October 2026 using an Apple M1 Pro, 8 CPU cores, 16 GB memory and Bun 1.3.14.

The generation form now selects classes explicitly, defaults to all current-year classes, scopes subject settings and progress to the selection, and preserves settings for retries. Requests and transactions remain sequential per class.

Measured changes

  • All 18 placements/unmet-workload digests and response sizes match the original code.
  • Period-definition and active subject-assignment list calls dropped from two per class to one in both modes.
  • Weekly teacher-unavailability list calls dropped from two per class to one. Free-mode lesson list calls dropped from three per class to two (discard plus the post-discard snapshot).
  • The largest free-mode case fell from 623.98 s to 203.35 s (67.4%).
  • Repeated 3-class/13-week free-mode median fell from 3.88 s to 2.53 s (34.9%). Weekly median changed from 1.08 s to 1.17 s; this does not demonstrate a weekly end-to-end speedup.
  • Solver-only five-run median fell from 912.26 ms to 256.92 ms (71.8%), with an identical output digest.

Measurement details

  • 18 combinations: 3, 10 and 30 classes; 1, 13 and 40 weeks; weekly and free generation.
  • Identical fixtures include shared teachers, active assignments, weekly teacher unavailability, a class-specific closure and existing standalone lessons in every class/week.
  • Generation requests run sequentially, each in its own transaction. Later requests see earlier committed sessions. Generated drafts are removed between runs; the fixture is otherwise unchanged.
  • One warmup and one recorded run per full-matrix combination. Repeated representative comparisons use one warmup and three recorded runs; solver-only uses five recorded runs.
  • The matrix overlapped with other verification/benchmark work on the same machine. Single-run wall times are exploratory, especially weekly-mode results. No timing limits were added to CI.
  • Database setup and fixture seeding are excluded. totalMs includes sequential workflow calls and JSON serialization, excluding browser and HTTP/network latency.
  • readMs and persistMs sum instrumented repository method durations, including authorization reads. Concurrent reads can overlap, so phase durations are not additive wall-time components.
  • queryCounts counts repository method invocations, not individual SQL statements within a method. solveMs and spreadMs measure the pure solver hooks.
  • Output digests cover class IDs, exact placements and unmet workloads; generated random session IDs are excluded. Identical response byte counts are also asserted.

Remaining performance options

  • Use set-based authorization checks for generated sessions, preserving all identity, placement and action-scope rules.

    The 30-class/40-week free fixture still invokes lessonSessions.findById and lessonSessions.assertAccess 8,400 times each. Authorization assertGenerate explicitly loops through every proposed session. Not implemented; requires policy-preserving design and authorization regression coverage.

  • Consider a smaller generation response or optional detail retrieval.

    The largest free fixture serializes 7,122,271 bytes, containing both sessions and placements. Response size was preserved. Not implemented; requires a separate HTTP contract decision. Network benefit is unmeasured.

  • Evaluate school-wide batching or background jobs with explicit partial-completion and progress semantics.

    Class requests intentionally remain sequential, preserving per-class commits and failure stopping behavior. Follow-up only; no batching, concurrency or background job changes.

Repeat the comparison

Run from package/domain-service. The baseline command prints its workflow module path. Use that path below. Run before and after sequentially on an otherwise idle machine.

bun run benchmark:timetable:baseline --ref 36bd773f7e4cb51cf4b61ea68c717c85deb44dbe
bun run benchmark:timetable --runs 3 --workflow <printed-workflow-path>
bun run benchmark:timetable --runs 3
Add --classes 3 --weeks 13; optionally add --modes weekly or --modes free.
bun run benchmark:timetable:solver --runs 5 --resolver <baseline-directory>/resolver.ts
bun run benchmark:timetable:solver --runs 5

The command prints a temporary workflow module path. It extracts only the original resolver and workflow from local Git, rewrites imports to shared current dependencies, and adds timing hooks without changing the original algorithms or reads.
